# 地铁线路规划原理指导（客观第一 · 详细可靠版）

> **最高原则：客观第一。** 一切线位、站位、走向、换乘决策必须以**可验证的客观证据**为依据（真实坐标/真实 path/道路中心线/图纸实测像素/工程规范），不得以主观拟合、目测美观或"看起来平滑"替代证据。每个决策记录证据来源与数值偏差；无证据不决策，证据冲突按优先级裁决并汇报。拟合只是弱模型备选工具，不是规划方法。

## 0. 客观证据优先级与裁决
1. **真实运营数据**：高德地铁 SUBWAY path / 地铁 POI 站台坐标（已开通/在建）。有则必须用，不得用图纸或估算覆盖。
2. **道路中心线**：高德 Driving/Walking 路径（沿道路红线）或底图道路矢量。用于无地铁数据段的线位与站位路口。
3. **规划图纸实测**：像素坐标经配准投影，只作走廊/站序/形状参考（大致参考），不作测量真值。
4. **工程规范**：曲线半径/坡度/站距/速度/站台长度等硬标准（见 §3）。
5. 估算/直线：仅 1–4 全缺且经用户同意，标注"估算"。
- 冲突裁决：真实运营 > 道路 > 图纸 > 规范自检 > 估算。图纸与道路冲突时，**形状拓扑以图纸为准、线位贴道路**；若道路完全不沿图纸走廊（实测偏差中位 >40m），保留图纸走廊形状但汇报"无对应道路"，不强行吸附错误道路。
- 每个交付附证据表：站坐标来源、线位来源、到道路偏差、到图纸偏差、曲线半径最小值、站距、换乘方向配对。

## 1. 需求与走廊（为什么这样走）
- 沿客流 OD 走廊（居住—就业—商业—枢纽）；串联铁路站/机场/公路枢纽/大型就业点。
- 骨干线求直达（少弯、大站距）、接驳/加密线求覆盖（多站、贴居住区）。
- 走廊选择证据：底图土地利用/既有网缺口/图纸走廊；不凭空造走廊。

## 2. 车站设置（客观定位）
- **站位必须落在客观节点**：道路交叉口、既有站台/在建站台、图纸站 dot、地标出入口。禁止把站放在街区中间或纯拟合点上。
- 站坐标取真实站台（resolveCoordTwice/queryLine 交叉一致）；无真实站台时取**道路交叉口坐标**（底图读取或道路中心线交点），并与图纸 dot 偏差汇报（≤ registration 容差）。
- 站距：城区 1–1.5km、郊区/市域 2–3km；相邻站距过短(<0.5km)或过长(>3km 城区)须说明理由。
- 站名以真实数据校正图纸误读（实测"螺蛳路"实为"螺塘路"）。
- 换乘站：先判方向配对（§4）再定站台形式；站坐标各线独立、不共用代表点。

## 3. 线形与工程标准（硬门禁）
- **贴道路中心线**：无地铁数据段线位应沿道路红线/中心线；控制点取道路中心线折点（交叉口/弯点），不得穿街区。验收：节点到道路中心线偏差中位 ≤30m、≥80% 点 ≤40m；不达标重布控制点。
- **曲线半径**：A 型一般≥350m、困难≥300m；B 型≥300m、困难≥250m；市域快线更大。验收：由控制点/节点算最小曲率半径 ≥ 车型困难值；不足则加大弯点间距或改线。
- **坡度**≤30–35‰（地下线排水/牵引限制）；游戏无高程时以"避免连续急弯+短站距配高速"作代理自检。
- **速度匹配**：城区 80–100km/h、市域 100–120km/h；站距与速度匹配（短站距不配高速）。
- **平滑但保形**：控制点经 Catmull-Rom/`fitSegmentNodes`+`curvatureThin` 平滑；控制点必须保留图纸/道路的**转弯拓扑**（过疏切弯实测 4 点切 113m 被拒、7 点 22.9m 通过）；栅格阶梯不得直接当节点。
- **形状保真**：设计线到图纸走廊偏差 ≤40m 且弯点顺序/数量与图纸一致（拓扑同构）；汇报最大偏差与弯点对应。

## 4. 换乘与同台方向（强制客观配对）
- 同台（跨站台）换乘成立前提=两线共站处**运行方向配对正确**：
  - 平行同向（A上行共B上行）→ 同向同台（最优，免楼梯）。
  - 平行反向（A上行对B下行）→ 反向同台（仅服务反向通勤，不得标同向）。
  - 交叉/垂直 → 节点/通道/叠岛换乘，不标同台。
- 设计共线/平行段**先定方向配对再定站台面/站层**；方向不匹配不设同台。
- 游戏 `isTransfer/transferGroupId` 只表达"可换乘"不表达方向；方向配对由平行走向+站序保证，汇报注明同向/反向/节点。
- 换乘距离/高差最小化：共站>通道>长通道；避免虚拟长换乘。

## 5. 线网与运营可行性
- 形态（放射+环/网格/枢纽放射）按城市结构；换乘节点分散客流，避免单枢纽过载。
- 折返/渡线/车辆段出入线定交路；预留短交路折返站、快车越行；环线闭合/支线分叉须有折返/联络线条件。
- 编组/车型匹配客流；分期预留延伸/支线（官方 startExtendLine/startBranchLine，不拆独立线）。

## 6. 客观验收清单（交付前逐项数值化）
| 项 | 门禁 | 测量方法 |
|---|---|---|
| 站坐标来源 | 真实站台或道路交叉口 | resolveCoordTwice 一致 / 底图路口 |
| 站到图纸 dot | ≤ registration 容差(默认250m) | 配准投影差 |
| 线位到道路中心线 | 中位≤30m 且≥80%≤40m | 节点到 driving/walking path 逐点距 |
| 线位到图纸走廊 | ≤40m 且弯点拓扑同构 | 节点到图纸投影 path 逐点距+弯点序 |
| 最小曲线半径 | ≥车型困难值 | 控制点三点曲率 |
| 站距 | 城区1–1.5km/市域2–3km | 相邻站 haversine |
| 站台避让 | 节点距两端站≥100m | haversine |
| 节点顺序 | 无折返/乱序 | hasNodeOrderIssue |
| 换乘方向 | 同向/反向/节点 明确 | 平行走向+站序 |
| 写回一致 | 站/节点≤2m | PlanMap.check |
- 任一不达标=不交付，回 §0 裁决重设计；不得放宽门禁掩盖。

## 7. 落到本技能
- 自主设计控制点：走廊=图纸+底图道路；站=真实站台/路口；线位贴道路中心线；经 `real.paths` 传 `PlanMap.prepare`，`fitSegmentNodes`+`curvatureThin` 平滑。
- **道路中心线客观读取**：路由 API（Driving/Walking）常因单行/规划路未收录而忽略 waypoints、返回非走廊路线（实测南京 2·9 加 4 个走廊 waypoints 仍中位 239m）→ 不可靠。改用**底图屏幕坐标反算**：截图读道路交叉口/弯点像素 → `G.map.containerPointToLatLng([x,y])` 得 GCJ 坐标 → 作为控制点/站位；再 `latLngToContainerPoint` 回投截图核对落在道路中心线上。此法以底图为客观证据，不依赖路由选路。
- 若底图亦无对应道路（规划路未建）：保留图纸走廊形状，汇报"无对应道路/未建"，不强行吸附错误道路。
- 几何门禁见 `plan-map-draw.md`；规划原理不替代几何门禁，二者同时满足才交付。
